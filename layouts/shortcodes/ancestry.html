{{- /* ancestry — the ancestry composition breakdown: rings, star rarity, drill-downs. {{< ancestry >}} reads site.Data.genes {{< ancestry "genes" >}} same thing, explicit SHAPE. data/genes.yaml holds tiers → groups → children. Tiers are headings, groups carry a ring, children are rows. That split is deliberate — see SCALING. RINGS. The circle trackers are the colophon's, same component: viewBox 0 0 36 36, r=15.9155 so the circumference is ~100 and `stroke-dasharray: " 100"` reads straight off as a percentage, rotated -90 so it starts at twelve o'clock. This section carries [data-perf-meters] and [data-perf-panel] so ts/perf-meters.ts picks the rings up and sweeps them on scroll — no toggle buttons here, which that module already tolerates (it only looks for them, it does not require them). Two departures from the colophon's version, both on purpose: STATIC FIRST. The colophon renders `stroke-dasharray="0 100"` and a literal `0`, and depends on JS to fill them in. Here the real values are in the HTML and the module resets to zero and sweeps back up. Identical on screen, but the numbers survive with JS off, which is what Product Principle 1 asks for. NO TRAFFIC LIGHT. The colophon colours by threshold — green ≥90, amber ≥50, red below. Those are Lighthouse's semantics and they are nonsense here: 54.4% British & Irish is not "needs improvement". Every ring is --c-accent, which also means the whole page swaps green→amber with the theme for free. RARITY. Two ratings per population, both derived — the head-count divided by the matching denominator in meta gives "1 in N", and the star count is the number of digits in N (see func/rarity-stars.html). Nothing is hand-assigned. Every rating is printed WITH its "1 in N", in the collapsed row and in the open detail. That pairing is load-bearing: more stars normally means more of a thing, so stars alone would read backwards, and the alternative was a key above the widget explaining which way the scale ran. A chart that needs a sentence telling you how to read it is a chart that hasn't finished. Seeing ★★★★☆ against "1 in 5,437" next to ★☆☆☆☆ against "1 in 5" settles the direction in one glance. A row can be missing an axis — there is no census line for Belarusian or Spanish ancestry — and a missing axis renders as an em dash with the reason underneath, not as zero stars. Zero stars would read as "vanishingly rare", which is the opposite of "nobody counted". SCALING. Every `pct` in the data file is a percentage of the whole report, and every ring's arc is that number, full stop. No normalising, no scaling a child against its parent. An early draft scaled children against their parent so Basque at 0.3% would be visible, and the result was a page where two identical arcs meant 31.5% and 1.2% depending on which group you had open. Children are text rows with a printed percentage instead — the honest version of the same information, and the reason only groups get rings. NO SOURCE LINKS. `source` is still in the data file for provenance; it is not rendered. This is a personal page, not a paper, and 21 SOURCE links were louder than anything they pointed at. ASSERTIONS. Children must sum to their group and groups to their tier, within 0.15 to absorb 23andMe's own rounding. These are warnf, not errorf: a report that genuinely does not sum is a real thing that could be pasted in here, and a hard build failure would be the wrong response to it. A missing data file IS an errorf — that one is always a mistake. THE GLOBE DRIVES THIS LIST. Every openable row carries `data-anc-node` with the population's name, which is the key the globe already has — ancestry-map.html hands it `{"ENG": {"name": "English", …}}` and the name is the join. Clicking England on the globe opens the English row, and its group above it, and marks it; opening a row that owns geography flies the globe there. See ts/ancestry-globe.ts. The name is the join rather than a code because a code would only work for the rows that have one. Basque and Ashkenazi Jewish have no polygon and never will, and they still have to be addressable if this hook is ever used for anything but the globe. `data-anc-current` is set by that module, so the highlight has to be declared HERE — Tailwind's `@source` covers layouts and content, not TypeScript, and a class name that only ever appears in a .ts file is a class name that never makes it into the stylesheet. `not-prose`: the page sets `prose: true`, and Typography would restyle the summary rows and the star rows.
