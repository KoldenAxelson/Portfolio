{{- /* ancestry-timeline — the datable events from the factoids, on one time axis. {{< ancestry-timeline >}} WHY VERTICAL. A horizontal axis is the prettier chart and the wrong one here. Eleven events with labels the length of "Steppe-derived Single Grave people replace those farmers" cannot sit side by side at phone width without either truncating to uselessness or needing a second, horizontal-only layout. Vertical reads identically at every width. IT IS STILL AN AXIS. Position down the spine is proportional to time, not to list order — the gaps mean something. That is the whole difference between this and a bulleted list with dots on it. LOG TIME. The axis is log(years before present). The events cluster hard: four between 4,476 and 5,900 years ago, then five between 1,036 and 1,500, then one. On a linear axis the entire Migration Period would be a smear at the bottom while two thirds of the chart sat empty. Log spreads them and keeps the ordering and the relative gaps honest — it just reads "orders of magnitude ago" rather than "years ago", which is the right unit for a range this wide. COLLISION. Proportional placement puts the Beaker event 50 years from the French one — half a pixel apart. So after computing the ideal offset, each event is pushed down to clear the previous one by MINGAP. Everything below a collision shifts with it, which compresses that stretch of the axis slightly; the alternative is two labels drawn on top of each other. The tick marks stay at the true position so the distortion is visible rather than hidden. No JS. No absolute positioning tricks that break when a label wraps — the spine is a border on a flow container and each event is a flow row with a computed top margin. */ -}} {{- $key := (.Get 0) | default "genes" -}} {{- $d := index site.Data $key -}} {{- $events := $d.timeline -}} {{- if not $events -}} {{- errorf "ancestry-timeline: data/%s.yaml has no `timeline` key (page: %s)" $key .Page.RelPermalink -}} {{- else -}} {{- /* Sort oldest first, then find the span the axis has to cover. */ -}} {{- $ev := sort $events "bp" "desc" -}} {{- $maxBP := (index $ev 0).bp -}} {{- $minBP := (index $ev (sub (len $ev) 1)).bp -}} {{- $logMax := math.Log (float $maxBP) -}} {{- $logMin := math.Log (float $minBP) -}} {{- $span := sub $logMax $logMin -}} {{- /* Pixels of track, how close two events may sit, and the rendered height of one event block — margin-top is the gap MINUS that height, because these are flow rows rather than absolutely positioned ones. */ -}} {{- $track := 560.0 -}} {{- $mingap := 68.0 -}} {{- $blockh := 46.0 -}} {{- /* Ideal position, then push down to clear the one above. `gap` is carried on each entry rather than derived at render time: `cond` evaluates BOTH of its arguments, so an (index $placed -1) guarded by `cond` still runs and still fails. Ask me how I know. */ -}} {{- $placed := slice -}} {{- $prev := 0.0 -}} {{- $prevBP := 0 -}} {{- $first := true -}} {{- range $ev -}} {{- $ideal := 0.0 -}} {{- if gt $span 0.0 }}{{ $ideal = mul (div (sub $logMax (math.Log (float .bp))) $span) $track }}{{ end -}} {{- $y := $ideal -}} {{- $gap := 0.0 -}} {{- $years := 0 -}} {{- if not $first -}} {{- if lt $y (add $prev $mingap) }}{{ $y = add $prev $mingap }}{{ end -}} {{- $gap = sub $y $prev -}} {{- $years = sub $prevBP .bp -}} {{- end -}} {{- $placed = $placed | append (dict "e" . "gap" $gap "years" $years) -}} {{- $prev = $y -}} {{- $prevBP = .bp -}} {{- $first = false -}} {{- end -}} {{- end -}}
