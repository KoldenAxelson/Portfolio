{{- /* dagea-globe — Dagea, a hand-drawn world, as a globe you can turn. {{< dagea-globe >}} WHAT IS ON THE PAGE, in the order it matters: 1. a static SVG map of the world, labelled, in the HTML; 2. a list of the six regions, as text, with what is in each; 3. a globe, which replaces (1) once it has geometry and has drawn a frame. That order is the whole design. The globe is the fun part and it is the part that needs JavaScript, a canvas, and a fetch to work — so it is third, and it is an enhancement over a page that is already complete without it. Product Principle 1: content behind a runtime is content that didn't ship. GEOMETRY comes from two committed files, both generated from the drawing by scripts/build-dagea-globe.py and neither fetched or regenerated at build time. data/dagea/map.json holds projected SVG paths for the flat map; assets/geo/dagea.json holds lon/lat rings for the globe, and is requested at runtime rather than inlined — 12 KB of coordinates in the HTML of a page some visitors will scroll past is 12 KB nobody asked for. NAMES come from data/dagea/regions.yaml, which the script never touches. See that file's header for the split. ONE COLOUR, NOT SIX. Every landmass is drawn in the same muted grey and the region under the pointer lights up in --c-accent. A six-way categorical palette was the obvious first move and it was wrong twice: it fights a site whose whole colour story is one accent that swaps green to amber with the theme, and it answers a question — "which region is this?" — that nobody is asking until they point at something. Highlight on demand says the same thing and says it about the thing you are actually looking at. THE LIST IS AN INPUT, not a legend. Each region is a button: hovering one lights that region on the globe, clicking one selects it and keeps it lit. Which means the globe is reachable without a pointer ever landing on a four-pixel islet in the Bagil Atoll — the six-item list is the accessible route to the same six things, and it is the version that works on a phone. `not-prose`, because the page sets `prose: true` and Typography would restyle the list and put margins on the figure's children. */ -}} {{- $map := index site.Data.dagea "map" -}} {{- $lore := index site.Data.dagea "regions" -}} {{- if or (not $map) (not $lore) -}} {{- errorf "dagea-globe: data/dagea/map.json or regions.yaml is missing — run scripts/build-dagea-globe.py (page: %s)" .Page.RelPermalink -}} {{- else -}} {{- $places := $lore.places -}} {{- /* Every NAMED place the map draws must have something to say about it. The auto-numbered islands (BGI4, ERK11…) are exempt on purpose and fall back to their region's island_note. */ -}} {{- range $code, $_ := $map.units -}} {{- if not (index $places $code) -}} {{- errorf "dagea-globe: map.json has region %q, which data/dagea/regions.yaml does not describe" $code -}} {{- end -}} {{- end -}} {{- range $code, $u := $map.subunits -}} {{- if not (findRE "[0-9]$" $code) -}} {{- if not (index $places $code) -}} {{- errorf "dagea-globe: map.json has subregion %q, which data/dagea/regions.yaml does not describe" $code -}} {{- end -}} {{- end -}} {{- end -}} {{- /* One resolved table for the panel, so the template and the TypeScript are never two opinions about the same place. Islands inherit their region's island_note rather than being listed forty times. */ -}} {{- $info := dict -}} {{- range $code, $p := $places -}} {{- $info = merge $info (dict $code (dict "name" $p.name "capital" $p.capital "export" $p.export "blurb" $p.blurb)) -}} {{- end -}} {{- range $code, $u := $map.subunits -}} {{- if not (index $info $code) -}} {{- $parent := index $places $u.parent -}} {{- $info = merge $info (dict $code (dict "name" $u.name "capital" "" "export" "" "blurb" ($parent.island_note | default ""))) -}} {{- end -}} {{- end -}} {{- $globe := resources.Get "geo/dagea.json" | fingerprint -}}
