{{- /* term — wrap a vocab word to make it a clickable definition. {{< term "validity" >}}validity{{< /term >}} key + the word as it reads in prose {{< term "standard-form" >}}standard form{{< /term >}} The key looks up data/glossary/.yaml (one source of truth). The button carries only the KEY — the definition text is not inlined per-word, because a definition can cross-reference other terms ([[key|display]]) and carry word lists, and those need lookup at click time from inside an already-open card. So the whole set ships once per page as a JSON blob and the client resolves keys against it (site/glossary.ts). Behavior lives in the global bundle: desktop opens a draggable window per term (site/definitions.ts), mobile replaces the top-nav panel (site/nav.ts). Only the CSS ships lazily, once per page, on pages that actually use a term. A bad key renders the plain word and logs a build warning, so a typo never breaks the page. */ -}} {{- $set := .Get "set" | default "basic-logic" -}} {{- $key := .Get 0 -}} {{- $glossary := index site.Data.glossary $set -}} {{- $entry := index $glossary $key -}} {{- $display := .Inner | default $key -}} {{- if $entry -}} {{- /* The set ships once per page, keyed by set name so a page can use two. */ -}} {{- $seen := printf "glossaryData-%s" $set -}} {{- if not (.Page.Scratch.Get $seen) -}} {{- .Page.Scratch.Set $seen true -}} {{- end -}} {{- if not (.Page.Scratch.Get "definitionsAssets") -}} {{- $css := resources.Get "css/definitions.css" | minify | fingerprint -}} {{- .Page.Scratch.Set "definitionsAssets" true -}} {{- end -}} {{- else -}} {{- warnf "term shortcode: no glossary entry %q in data/glossary/%s.yaml" $key $set -}} {{ $display }} {{- end -}}
