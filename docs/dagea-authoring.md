# Dagea — authoring guide

`/dagea/` is the gazetteer: what a literate person inside the world could tell you.
`/misc/dagea/` is the map. This is how to add to either.

## The transcription contract

Every article under `content/dagea/` is a **player-facing rewrite** of a note in the
Dagean Vault, not a copy of it. The vault is a separate repository, is not read at
build time, and is canon; these pages drift from it until somebody re-transcribes.
The test applied to every sentence: *would this be on a normal encyclopedia page for
this place?*

- **In:** geography, climate, economy, faith, custom, history, current events an
  ordinary traveller or merchant would notice.
- **Out:** anything a player is supposed to discover — motives behind events, who is
  actually doing what and why, anything from a DM Notes callout.
- **The supernatural appears the way it would in a real gazetteer:** as what people
  say, what travellers report, what scholars argue about. Never as mechanism. The
  vault knows how it works; this page knows the story.

`source:` in front matter is the vault path, printed at the foot of the page as
provenance. It is deliberately not a link — the vault is not published.

## Where things live

```
content/dagea/
  _index.md                ← the overview; its table lists the topics
  regions/_index.md        ← a TOPIC INDEX. title "Dagea Regions", linkTitle "Regions"
  regions/feldia.md        ← an article
  factions/ history/ bestiary/   ← same shape
content/misc/
  dagea.md                 ← the globe
data/dagea/
  regions.yaml             ← what to say about each place on the map (hand-written)
  map.json                 ← geometry, GENERATED by scripts/build-dagea-globe.py
layouts/dagea/
  list.html                ← the overview AND every topic index (one template)
  single.html              ← one article
layouts/partials/
  func/dagea-menu.html     ← the navigation, as data. One source, two surfaces.
  dagea-nav.html           ← the desktop FAB
  dagea-globe.html         ← (shortcode) the map
```

## Adding a topic

Create `content/dagea/<topic>/_index.md`. That is the whole job — the overview's
table, the navigation FAB and the mobile navbar menu all discover it.

```yaml
---
title: "Dagea People"        # "Dagea <Topic>", not "<Topic>"
description: "One line. It is the overview table's third column."
linkTitle: "People"          # the short form, for menus
lead: "A line under the H1"
icon: "user"                 # any key from data/icons.yaml
weight: 50                   # menu and table order
---
```

**Titles are "Dagea &lt;Topic&gt;".** These pages are reached from search results and
from browser history as often as from the site, and "Regions" on its own does not say
which world's. `linkTitle` is the short form so a menu that is already Dagea's does
not say the word five times.

**No prose in a topic index.** The table is the content. A paragraph explaining what
a region is would be a paragraph between the reader and the twenty links they came
for. `.Content` renders above the table for the rare index that needs a sentence;
most need none.

## Adding an article

Drop a `.md` in the topic folder. `summary:` is what the index table shows, so write
it as one line that distinguishes this article from its nineteen neighbours.

`region:` ties the article to a code in `data/dagea/regions.yaml`. It powers the
index's "Within" column and the footer's link to the map, and an unknown code is a
build error. It is optional — nothing outside `regions/` uses it today.

**Do not use `type:`.** Hugo reads it as the layout lookup directory, so
`type: region` sends it hunting for `layouts/region/single.html`. The folder the file
sits in already says what kind of article it is.

## The navigation

`partials/func/dagea-menu.html` returns the menu as a slice of
`{label, href, icon, current}`, or an empty slice off a non-Dagea page. Two things
render it: `partials/dagea-nav.html` (the desktop FAB) and `partials/topnav.html`
(the mobile navbar list). It used to be written twice per surface for Basic Logic and
again for the campaign page; here it is written once.

**The map is the one hard-coded entry**, because it lives at `/misc/dagea/` rather
than under `/dagea/` — it is a toy about the world rather than an article in it — so
nothing in the section tree can find it. It is looked up with `site.GetPage` rather
than written as a literal path, so moving the file is a build error instead of a dead
row.

**The globe page identifies itself with `.HasShortcode "dagea-globe"`.** That is
exact and evaluated per build, so it needs no front-matter flag that could go stale.

## The things that will bite you

- **The corner is contested.** Every aux FAB is `fixed bottom-6 right-6 z-30`, and so
  is the AI chat trigger — which renders after them in `baseof.html`, wins the equal
  z-index, and takes the click. `auxiliary-button.css` now steps the aux FAB up by its
  own height whenever `html[data-ai-ok]` is set, which is the same signal that reveals
  the chat button. Before that, the CV actions, the Basic Logic chapter select and the
  Skyrim/campaign section navs were all unreachable whenever the chat backend was up.
- **`$` inside a `range` is the LIST page, not the item.** Comparing an article's
  region name against `$.Title` compares it to "Dagea Regions", which is never equal —
  so the column printed on every row. Capture `$title := .Title` at the top of the
  iteration.
- **`{{-` eats the newline before it.** `On the map:` followed by a left-trimmed
  comment renders as `On the map:Kornfeld`.
- **Geometry is generated; words are not.** `scripts/build-dagea-globe.py` overwrites
  `data/dagea/map.json` and `assets/geo/dagea.json` from the drawing and never touches
  `regions.yaml`. Shapes come from the picture, words come from a person.
